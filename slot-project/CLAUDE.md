# CLAUDE.md — slot-project (Neon Fortune)

Guidance for Claude Code working in this directory. See `README.md` for the overview.

## Source-of-truth flow (important)

```
math/neon_fortune.json  ← the only math source of truth
   ├→ sdk (loaded at runtime) / slotsim verification → math/neon_fortune.sim.json
   ├→ docs/math_spec.xlsx (generated by tools/build_math_spec.py. Theoretical values are Excel formulas)
   └→ unity/Assets/_Game/Resources/Math/neon_fortune.json (copied by make_specs.sh)
docs/game_spec.xlsx ← tools/build_game_spec.py   ↔ keep in sync by hand with unity/.../GameSpec.cs
```

- **Don't hand-edit the .xlsx files.** Change the generator scripts and regenerate. (Math edited by the user in Excel comes back via `tools/export_math.py`)
- After changing the math, always run `./tools/make_specs.sh`. If any of the 3 verifications (theory = full cycle, MC within ±4σ) FAILs, don't commit.
- Changing timings, colors, or thresholds in the game spec means changing both `tools/build_game_spec.py` and `unity/Assets/_Game/Scripts/Runtime/GameSpec.cs`.

## Premises of the math calculation (the formulas break if these are violated)

- No WILD on reel 1 (the paying symbol = reel 1's symbol)
- WILD has no pay of its own
- SCATTERs on the same reel are at least 3 apart (at most 1 visible per reel)
- Free spins use the same reels as the base game, × multiplier, unlimited retriggers

`MathModel.Validate()` and `tools/slotmath.py` check these. To change the rules, update the Excel formulas, TheoreticalCalculator, and slotmath.py together.

## SDK conventions

- `sdk/package/Runtime` is shared by Unity and .NET: netstandard2.1, C# 9, **no dependencies** (no System.Text.Json → use MiniJson)
- Keep the fast paths allocation-free (`SpinEvaluator.EvaluateUnits`). The simulator does 100M rounds in about 10 seconds
- Principle: results (stops, wins, state) are decided only by the SDK; presentation never changes them

## Honesty

This project is a hobby project that doesn't handle real money. Don't write about it as if it were a production casino game or certified.
Separate "ran and verified" from "only compile-checked" (see the verification status table in the README).
